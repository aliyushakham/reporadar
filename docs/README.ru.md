# RepoRadar — карта незнакомого Python-проекта

**Задача:** помочь разработчику найти нужный код и понять, какие функции и разделы
документации стоит проверить при изменении. Все результаты сопровождаются исходным
текстом и номерами строк.

## Запуск

```bash
python3 -m reporadar serve examples/shop
```

Открой http://127.0.0.1:8765. Для своего проекта передай путь вместо `examples/shop`.
Сторонние Python-библиотеки и ключи API не нужны.

## Сценарии

1. **Разобраться в проекте.** Найти функцию по названию или словам из описания,
   прочитать исходник, перейти к вызываемым функциям.
2. **Подготовить изменение.** Выбрать функцию, посмотреть вызывающие функции и
   цепочки доказательств; открыть найденную документацию.
3. **Проверить изменения.** Создать снимок, изменить код, нажать Re-index и сравнить
   снимки в Snapshot history.
4. **Автоматизировать проверку.** Импортировать workflow n8n: запуск → HTTP-запрос
   индексирования → сохранение снимка в SQLite → краткий отчёт или ветка ошибки.

## Соответствие задачам стажировки Т1

| Задача вакансии | Реализация |
|---|---|
| AST-анализ кода | Обход синтаксического дерева, функции, классы, импорты, вызовы, fingerprints |
| Изучение текста и структуры документов | Секции Markdown, заголовки, fenced code, поиск связанного текста |
| Workflow в n8n | Готовый JSON workflow с ручным/webhook запуском, HTTP, retry и веткой ошибки |
| SQL-скрипты | Схема SQLite, агрегации, рекурсивный CTE для вызывающих функций |
| Автоматизация на Python | CLI, HTTP API, индексирование, сравнение снимков, расчёт метрик |
| Декомпозиция и документация | Разделённые модули, тесты, архитектурные решения и описание ограничений |

Соответствие относится к опубликованным задачам вакансии. Проект не заменяет знание
основ Python/SQL и не гарантирует результат отбора.

## Где здесь NLP

Токенизация кода и текста, разделение snake_case/camelCase, BM25, расширение русских
запросов небольшим словарём и ранжирование фрагментов документации. Есть сравнение
трёх методов и воспроизводимый расчёт Recall@5, MRR@5, nDCG@5.

Это инженерный NLP/IR-проект без обучения нейросети. Не стоит заявлять в резюме
fine-tuning, полноценный семантический поиск или RAG-генерацию: их в этой версии нет.

## Что означают связи

`A → B` означает: внутри исходника A найден вызов, который статический анализатор
связал с B. Это не трасса реального выполнения. Для наследования, DI и динамических
вызовов нужна дополнительная информация; неизвестные связи показываются отдельно.

Секция документации, найденная поиском, — предложение для проверки, а не доказанная
ошибка. После изменения кода пользователь оценивает, нужно ли обновлять документ.
